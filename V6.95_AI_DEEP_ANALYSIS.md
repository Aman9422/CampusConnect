# CampusConnect v6.95 — AI Deep Analysis Integration

**Date:** March 2, 2026  
**Type:** Major Feature Upgrade  
**Summary:** Replaced rule-based deep analysis with real AI integration using open-source hosted LLM APIs (Groq / HuggingFace Inference Providers) via Firebase Cloud Functions.

---

## What Changed

### Problem
All resume analytics in v6.9 were rule-based — static keyword matching, template-driven insights, and hard-coded advice. No actual AI was involved in the "AI-Powered" system.

### Solution
Introduced a server-side AI Provider Abstraction Layer that calls real LLM APIs (Groq LLaMA 3.1 8B, HuggingFace LLaMA 3.1 8B via Inference Providers) from Cloud Functions, keeping API keys secure and providing genuine AI-powered resume analysis.

---

## Architecture

```
Flutter Client                    Firebase Cloud Functions
     │                                     │
     ├─ requestAIAnalysis() ──────────────►│ generateResumeAnalysis (onCall)
     │   (cloud_functions SDK)             │   ├─ Auth check (uid from context)
     │                                     │   ├─ Cache check (return if exists)
     │                                     │   ├─ Usage limit (3/month)
     │                                     │   ├─ aiProvider.js (abstraction)
     │                                     │   │   ├─ groqProvider.js ─► Groq API
     │                                     │   │   └─ huggingfaceProvider.js ─► HF API
     │                                     │   ├─ normalizeResponse.js
     │                                     │   └─ Save to Firestore
     │◄──────────────────────────────────── │ Return structured JSON
     │                                     │
     ├─ Update local cache                 │
     └─ Display in Resume Insights UI      │
```

## Files Created

### Cloud Functions (`/functions/ai/`)

| File | Purpose |
|------|---------|
| `ai/aiProvider.js` | AI Provider Abstraction Layer — routes requests to Groq or HuggingFace based on `process.env.AI_PROVIDER` environment variable. Contains structured system prompt requesting strict JSON output. |
| `ai/groqProvider.js` | Groq provider — calls `llama-3.1-8b-instant` model via Groq API with JSON mode enabled, 30s timeout, 2048 max tokens. |
| `ai/huggingfaceProvider.js` | HuggingFace Inference Providers — calls `meta-llama/Llama-3.1-8B-Instruct` via OpenAI-compatible endpoint (`router.huggingface.co/v1/chat/completions`). Auto-routes to fastest provider (Cerebras, SambaNova, etc.), 60s timeout. |
| `ai/normalizeResponse.js` | Response normalizer — extracts JSON from markdown code blocks or raw text, validates all fields, handles partial/malformed JSON recovery, applies type coercion and defaults. |

## AI Response Format

The structured prompt requests this exact JSON from the LLM:

```json
{
  "summary": "2-3 sentence professional assessment",
  "strengths": ["strength1", "strength2", "strength3"],
  "weaknesses": ["weakness1", "weakness2", "weakness3"],
  "missingSkills": ["skill1", "skill2", "skill3"],
  "careerSuggestions": ["suggestion1", "suggestion2", "suggestion3"],
  "improvementRoadmap": {
    "30_days": ["action1", "action2", "action3"],
    "60_days": ["action1", "action2", "action3"]
  }
}
```

## Usage Limiting

- **3 AI deep analysis calls per month** per user
- Validated server-side in Cloud Function (cannot be bypassed)
- Counter auto-resets when month changes
- Returns `resource-exhausted` error with clear message when limit hit
- Client shows remaining count and blocked reason in UI

---

## Security Model

- **API keys stored server-side only** — `process.env.GROQ_API_KEY` / `process.env.HUGGINGFACE_API_KEY`
- **Never exposed to Flutter client** — all AI calls routed through Cloud Function
- **Auth required** — `request.auth.uid` extracted from Firebase Auth context (onCall)
- **Input sanitized** — Resume text trimmed and capped at 5000 chars, target role at 100 chars
- **Max tokens limited** — 2048 tokens prevents runaway API costs
- **Cached results** — If `aiAnalysis` already exists for a review, returns cached (no re-call)

## Provider Switching

Switch AI provider via environment variable:

```bash
# Use Groq (default) — fastest, free tier generous
AI_PROVIDER=groq

# Use HuggingFace — open-source models, free tier available
AI_PROVIDER=huggingface
```

### Provider Comparison

| Feature | Groq | HuggingFace |
|---------|------|-------------|
| Model | LLaMA 3.1 8B Instant | LLaMA 3.1 8B Instruct |
| API Format | OpenAI-compatible | OpenAI-compatible (via Inference Providers) |
| Speed | ~2-5 seconds | ~3-15 seconds (varies by provider) |
| JSON Mode | Native (`response_format`) | Prompt-based |
| Providers | Groq LPU hardware | Auto-selects: Cerebras, SambaNova, Novita, etc. |
| Free Tier | Generous (30 RPM) | Free tier with HF token |
| Timeout | 30 seconds | 60 seconds |

## Deployment Steps

```bash
# 1. Create functions/.env file with API keys
cd functions
# Add these lines to .env:
#   AI_PROVIDER=groq
#   GROQ_API_KEY=gsk_your_key_here
#   HUGGINGFACE_API_KEY=hf_your_token_here

# 2. Deploy Cloud Functions
firebase deploy --only functions

# 3. Deploy Firestore rules
firebase deploy --only firestore:rules

# 4. Flutter client — no additional setup needed
# (uses cloud_functions SDK already in pubspec.yaml)
```

### Getting API Keys

**Groq (recommended, faster):**
1. Go to https://console.groq.com
2. Sign up / log in with Google
3. Navigate to **API Keys** in the left sidebar
4. Click **Create API Key** → copy the key (starts with `gsk_`)

**HuggingFace (fallback):**
1. Go to https://huggingface.co/settings/tokens
2. Click **Create new token** → select **Fine-grained**
3. Enable **"Make calls to Inference Providers"** permission
4. Create → copy the token (starts with `hf_`)

## Known Limitations

- Resume raw text is not stored in history — AI analysis uses review metadata as context
- HuggingFace provider response time varies by which inference provider is selected
- No streaming/progressive display of AI results
- AI analysis is per-review (not cross-review trend analysis yet)
- 3/month AI limit is per-user, not configurable from client
