## 🔥 Phase 1: Real-Time Chat System

### 1.1 Chat Creation (Auto-generated)
**Test Scenario**: Chat auto-creation when alumni accepts mentorship request

**Steps**:
1. Login as **Student** → Navigate to Mentorship Requests
2. Send mentorship request to an alumni
3. Login as **Alumni** → Go to pending requests
4. Accept the mentorship request
5. **VERIFY**: Chat is auto-created and navigation happens immediately

**Expected Results**:
- ✅ Chat appears in both users' chat lists
- ✅ Chat contains mentorship context (title, alumni info)
- ✅ Navigation to chat happens automatically after acceptance
- ✅ "Open Chat" button appears in mentorship request detail view

### 1.2 Real-Time Messaging
**Test Scenario**: Back-and-forth messaging with live updates

**Steps**:
1. Open chat on **two devices/browsers** (student + alumni accounts)
2. Send message from student device
3. **VERIFY**: Message appears instantly on alumni device
4. Send reply from alumni device
5. **VERIFY**: Reply appears instantly on student device
6. Send 5-10 messages back and forth rapidly

**Expected Results**:
- ✅ All messages appear in real-time (< 2 seconds)
- ✅ Message bubbles show correct alignment (right=sender, left=receiver)
- ✅ Timestamps display correctly
- ✅ No duplicate messages or missing messages
- ✅ Auto-scroll to latest message works

### 1.3 Unread Count & Status
**Test Scenario**: Unread badge and mark-as-read functionality

**Steps**:
1. Student sends message to alumni
2. **VERIFY**: Unread badge appears on alumni's chat list and app icon
3. Alumni opens the chat
4. **VERIFY**: Unread count resets to 0
5. Alumni sends reply, then leaves chat
6. Student checks chat list
7. **VERIFY**: Unread badge shows on student side

**Expected Results**:
- ✅ Unread badges appear/disappear correctly
- ✅ Chat list shows unread count per conversation
- ✅ App-wide unread count in navigation badges
- ✅ markChatAsRead() resets count when chat is opened

### 1.4 Chat Navigation & UI
**Test Scenario**: Chat access from multiple entry points

**Steps**:
1. Navigate to chat via **Chat List** (from nav icon)
2. Navigate to chat via **Notification tap** (mentorship accepted)
3. Navigate to chat via **"Open Chat" button** (mentorship detail view)
4. Test **back navigation** from chat to previous screen

**Expected Results**:
- ✅ All navigation paths lead to the same chat
- ✅ Chat history loads correctly from all entry points
- ✅ Back navigation works without losing message draft
- ✅ Chat list shows last message preview and timestamp

2. **VERIFY**: Student receives notification immediately
3. Tap notification → should navigate directly to new chat

**Steps for mentorshipRejected**:
1. Alumni rejects mentorship request
2. **VERIFY**: Student receives notification immediately
3. Tap notification → should navigate to mentorship request detail

**Expected Results**:
- ✅ All notifications appear in real-time (< 3 seconds)

- ✅ No notification spam (properly throttled for rapid messages)

## 📊 Phase 3: Teacher Analytics Enhancement

### 3.1 Analytics Data Aggregation
**Test Scenario**: Teacher dashboard shows real student resume data

**Prerequisites**: Create resume reviews for multiple students first
1. Login as **Students** → Complete resume reviews (different scores)
2. Ensure varied ATS scores (some 90+, some 70+, some 50+, some <40)

**Testing Steps**:
1. Login as **Teacher** → Navigate to Student Analytics
2. **VERIFY**: "Resume Review Aggregates" section loads
3. Check metric cards show: Total Reviews, Average Score
4. **VERIFY**: Pie chart displays score distribution
5. Check categories: Excellent (80+), Good (60-79), Fair (40-59), Poor (<40)

**Expected Results**:
- ✅ Real data loads from Firestore CollectionGroup query
- ✅ Aggregate calculations are mathematically correct
- ✅ Pie chart renders with proper color coding
- ✅ No loading errors or empty states with real data

### 3.2 Student Resume Leaderboard
**Test Scenario**: Top students by resume score ranking

**Steps**:
1. Same teacher dashboard → scroll to "Top Students by Resume Score"
2. **VERIFY**: Shows top 10 students ordered by latest ATS score
3. Check data includes: Student name, Latest score, Review count
4. **VERIFY**: Badge colors match score ranges (green=80+, yellow=60+, red=<60)

**Expected Results**:
- ✅ Leaderboard shows real student data
- ✅ Sorting by `latestScore` descending is correct
- ✅ Score badges display with proper colors
- ✅ Review count aggregation is accurate

### 3.3 Analytics Performance
**Test Scenario**: Analytics load time and refresh capability

**Steps**:
1. Clear app cache → Login as Teacher
2. Navigate to Student Analytics → **measure load time**
3. Pull-to-refresh the analytics data
4. **VERIFY**: Refresh updates with latest data

**Expected Results**:
- ✅ Initial load < 5 seconds with real data
- ✅ Refresh functionality works smoothly
- ✅ No memory leaks during repeated refreshes
- ✅ Handles empty data states gracefully

## 🤝 Phase 4: Mentorship Completion Flow

### 4.1 Completion UI Access
**Test Scenario**: "Mark as Completed" button appears correctly

**Steps**:
1. Ensure you have an **accepted mentorship** (status = accepted)
2. Navigate to mentorship request detail view
3. **VERIFY**: "Mark as Completed" button is visible
4. Test with **pending** mentorship → button should NOT appear
5. Test with **already completed** mentorship → should show completion info

**Expected Results**:
- ✅ Button only appears for accepted, non-completed mentorships
- ✅ Button matches AppTheme styling (green success color)
- ✅ Completed mentorships display rating and feedback (if available)

### 4.2 Completion Form & Validation
**Test Scenario**: Rating and feedback submission

**Steps**:
1. Click "Mark as Completed" → opens CompleteMentorshipView
2. **VERIFY**: Mentorship summary displays (title, alumni name, skills)
3. Test rating selection (tap different stars)
4. **VERIFY**: Rating text updates ("Excellent", "Good", etc.)
5. Try submitting without rating → should show error
6. Add rating + optional feedback → submit

**Expected Results**:
- ✅ Star rating widget is interactive and updates visually
- ✅ Feedback form accepts multi-line text (500 char limit)
- ✅ Form validation prevents submission without rating
- ✅ Success message appears after completion

### 4.3 Completion Data Persistence
**Test Scenario**: Completed mentorship data saves correctly

**Steps**:
1. Complete a mentorship with 4-star rating + feedback
2. Navigate back to mentorship detail
3. **VERIFY**: Shows completion date, rating stars, feedback text
4. Check Firestore directly → verify `completedAt`, `rating`, `feedback` fields
5. Test with rating-only (no feedback) → should save correctly

**Expected Results**:
- ✅ All completion data persists in Firestore
- ✅ UI displays completion info for already-completed mentorships
- ✅ Optional feedback field handles both empty and filled states
- ✅ Status changes from "accepted" to "completed"

## 🔄 Phase 5: End-to-End Integration Testing

### 5.1 Complete Mentorship Journey
**Test Full Workflow**: Request → Accept → Chat → Complete

**Steps**:
1. **Student**: Send mentorship request to alumni
   - ✅ Alumni receives `mentorshipRequested` notification
2. **Alumni**: Accept the mentorship request
   - ✅ Student receives `mentorshipAccepted` notification with chat link
   - ✅ Chat is auto-created
   - ✅ Navigation happens to new chat
3. **Both**: Exchange messages in chat
   - ✅ Real-time messaging works for both participants
   - ✅ `newMessage` notifications work when other user is outside chat
4. **Either**: Mark mentorship as completed
   - ✅ Completion form saves rating and feedback
   - ✅ Status updates to "completed"
   - ✅ Completion info displays in detail view

**Expected Results**:
- ✅ Entire flow works seamlessly without manual intervention
- ✅ All notifications trigger at correct times
- ✅ No data inconsistencies between mentorship and chat
- ✅ Experience feels connected and intuitive

### 5.2 Multi-User Concurrent Testing
**Test Scenario**: Multiple users active simultaneously

**Setup**: 3 devices/browsers (1 student, 1 alumni, 1 teacher)

**Steps**:
1. **Student & Alumni**: Active chat conversation (sending messages)
2. **Alumni**: Simultaneously creates job opportunity
3. **Teacher**: Viewing analytics dashboard (refreshing data)
4. **Verify**: All features work concurrently without conflicts

**Expected Results**:
- ✅ No performance degradation with concurrent users
- ✅ Real-time features work for all users simultaneously
- ✅ No data corruption or race conditions
- ✅ Notifications deliver to correct users only

## 🚨 Phase 6: Error Handling & Edge Cases

### 6.1 Network Connectivity Testing
**Test Scenarios**: Offline/online transitions

**Steps**:
1. **Disconnect internet** during active chat
2. Try sending messages → should queue or show error
3. **Reconnect internet** → verify messages sync
4. Test notification delivery after network restoration

**Expected Results**:
- ✅ Graceful offline handling (no app crashes)
- ✅ Messages sync when connectivity restored
- ✅ Notifications catch up after network recovery
- ✅ User feedback for network status

### 6.2 Large Data Volume Testing
**Test Performance**: Heavy usage simulation

**Steps**:
1. Create chat with **100+ messages**
2. Verify chat loads and scrolls smoothly
3. Create **20+ notifications** → check notification list performance
4. Analytics with **50+ students** → verify load time

**Expected Results**:
- ✅ Chat pagination handles large message history
- ✅ Notification list remains responsive
- ✅ Analytics aggregation completes in reasonable time
- ✅ No memory leaks or UI freezing

### 6.3 Invalid Data Handling
**Test Robustness**: Corrupted or missing data

**Steps**:
1. Test chat with missing participant names → should handle gracefully
2. Notification with missing data fields → should not crash
3. Analytics with malformed resume data → should skip invalid entries

**Expected Results**:
- ✅ App doesn't crash with invalid/missing data
- ✅ Fallback values display appropriately
- ✅ Error logging for debugging purposes
- ✅ User-friendly error messages
