## 1. Firestore Structure

### Users Collection
```
users/{uid}
├── personal: {
│     fullName: string,
│     email: string,
│     phone: string,         // Contact number
│     avatarUrl: string      // Profile picture URL
│   }
├── academic: {
│     college: string,
│     program: string,
│     year: number (1-4),
│     cgpa: number (0-10)
│   }
├── career: {
│     interests: string[],
│     preferredRoles: string[]
│   }
├── metadata: {
│     createdAt: Timestamp,
│     updatedAt: Timestamp
│   }
└── profileCompleted: boolean   // ← ROOT LEVEL
```

### Placement Applications (UID-Scoped)
```
placements/{placementId}/applications/{uid}
├── userId: string
├── placementId: string
├── resumeUrl: string
├── company: string
├── appliedAt: Timestamp
└── status: "applied" | "reviewing" | "accepted" | "rejected"
```

## 5. Auth State Management (Critical Fix)

### Problem Solved: Data Leakage Between Users
Previously, when User A logged out and User B logged in, User B would briefly see User A's profile data.

### Solution: AuthGuard Refactored
- Changed from `StatelessWidget` with `FutureBuilder` to `StatefulWidget` with `StreamBuilder`
- Uses `authStateChanges` stream for real-time auth state
- Added `_isLoggedOut` flag to prevent race conditions

### Auth Service Enhancement:
```dart
// Added to auth_provider.dart, firebase_auth_provider.dart, auth_service.dart
Stream<AuthUser?> get authStateChanges;
```

### Provider Lifecycle Management:
All providers now have `_isDisposed` flag:
```dart
bool _isDisposed = false;

void reset() {
  _isDisposed = true; // Mark as disposed FIRST
  // ... reset state
}

Future<void> init() async {
  if (_isDisposed || userId == null) return;
  _isDisposed = false;
  // ... initialization
}
```

## 6. Firestore Security Rules

### Complete Rules (firestore.rules):
```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function isAuthenticated() {
      return request.auth != null;
    }

    function isOwner(userId) {
      return isAuthenticated() && request.auth.uid == userId;
    }

    match /users/{userId} {
      allow read, write: if isOwner(userId);
      match /{subcollection=**} {
        allow read, write: if isOwner(userId);
      }
    }

    match /placements/{placementId} {
      allow read: if isAuthenticated();
      allow write: if false;
      match /applications/{appUserId} {
        allow create: if isOwner(appUserId);
        allow read: if isOwner(appUserId);
        allow update, delete: if false;
      }
    }

    match /applications/{applicationId} {
      allow read: if isAuthenticated() && resource.data.userId == request.auth.uid;
      allow create: if isAuthenticated() && request.resource.data.userId == request.auth.uid;
      allow update, delete: if false;
    }

    match /notes/{noteId} {
      allow read: if isAuthenticated();
      allow create: if isAuthenticated();
      allow update, delete: if isAuthenticated() && resource.data.userId == request.auth.uid;
    }

    match /ai_conversations/{conversationId} {
      allow read: if isAuthenticated() && resource.data.userId == request.auth.uid;
      allow write: if false;
    }

    match /ai_usage/{userId} {
      allow read: if isOwner(userId);
      allow write: if false;
    }

    match /ai_rate_limits/{userId} {
      allow read: if isOwner(userId);
      allow write: if false;
    }

    match /ai_spam_check/{userId} {
      allow read: if isOwner(userId);
      allow write: if false;
    }

    match /analytics_events/{eventId} {
      allow read, write: if false;
    }

    match /{document=**} {
      allow read, write: if false;
    }
  }
}
```

### Security Summary:
| Attack Vector | Protected? |
|--------------|------------|
| User reads another user's profile | ✅ Blocked |
| User modifies another user's profile | ✅ Blocked |
| User deletes someone else's application | ✅ Blocked |
| User edits placements data | ✅ Blocked |
| Unauthenticated access | ✅ Blocked |
| Data leakage between users on logout | ✅ Fixed |

### Deploy Command:
```bash
firebase deploy --only firestore:rules
```

## 9. Known Behaviors

### Firestore Offline Cache After Logout
After logout, you may see a few Firestore "Write failed" warnings:
```
W/Firestore: Write failed at users/{uid}: PERMISSION_DENIED
```

**This is expected.** Firestore's offline persistence queues writes, and pending writes fail when auth becomes null. These stop after a few retries and don't affect functionality.
