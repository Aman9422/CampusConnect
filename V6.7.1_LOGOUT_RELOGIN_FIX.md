# CampusConnect v6.7.1 - Logout/Re-Login Race Condition Fix

**Status: ✅ COMPLETE** (February 12, 2026)

## Overview

v6.7.1 is a **critical patch** that fixes a race condition in the AuthGuard lifecycle where providers (Placements, Profile, AI, Notifications, Resume Review) lost their state after a logout → re-login cycle, causing screens like Placements to show empty with `"Cannot load applications: userId is null"`.

---

## Problem

### Symptoms
- After logout → re-login, Placements tab shows **"No placements available"**
- Debug console floods with `Cannot load applications: userId is null`
- Firestore PERMISSION_DENIED errors during logout transition
- All provider-dependent screens fail to load data on re-login

### Root Causes

**1. `_handleLogout()` callback not guarded against re-login**

The AuthGuard's `else` branch (user == null) scheduled `_handleLogout()` via `addPostFrameCallback`, but only checked `if (mounted)` — **not** `if (_isLoggedOut)`. When a user logged back in quickly, the callback still fired and nuked all provider state *after* providers had already been re-initialized.

```
Timeline:
1. Logout  → StreamBuilder fires user==null → schedules _handleLogout() callback
2. Login   → StreamBuilder fires user!=null → _isLoggedOut=false → schedules initWithUser()
3. Frame   → _handleLogout() runs FIRST (scheduled first) → reset() on ALL providers → userId=null
4. Frame   → initWithUser() runs but providers already thrashed by reset's notifyListeners()
```

**2. `pushNamedAndRemoveUntil(loginRoute)` bypassing AuthGuard**

All logout handlers in views pushed a **new LoginView route on top of the AuthGuard widget**, so when the user logged back in from that orphaned route, the AuthGuard's `StreamBuilder` wasn't driving the navigation — providers were never re-initialized.

**3. Consumer rebuild scheduling multiple init callbacks**

The `Consumer<ProfileProvider>` builder could fire multiple times during initialization, scheduling duplicate `initWithUser()` post-frame callbacks that competed with each other.

## Fix Summary

| Root Cause | Fix | File |
|------------|-----|------|
| `_handleLogout` fires after re-login | Guard callback with `if (mounted && _isLoggedOut)` | `main.dart` |
| Double-scheduled init callbacks | Added `_providerInitScheduled` flag | `main.dart` |
| `pushNamedAndRemoveUntil` bypasses AuthGuard | Removed from all logout handlers; let AuthGuard handle navigation | `notes_view.dart`, `profile_view.dart`, `verify_email_view.dart` |
| Missing provider resets on logout | Added `NotificationsProvider.reset()` and `ResumeReviewProvider.reset()` | `profile_view.dart`, `verify_email_view.dart` |

## Detailed Changes

### main.dart — AuthGuard

**New state flag:**
```dart
bool _providerInitScheduled = false; // Prevent double-scheduling init callbacks
```

**Re-login detection (user != null branch):**
```dart
if (_isLoggedOut) {
  _isLoggedOut = false;
  _providerInitScheduled = false; // Allow fresh init on re-login
}
```

**Init scheduling guard:**
```dart
// Before (v6.7): Could schedule multiple times from Consumer rebuilds
if (!profileProvider.isInitialized) {

// After (v6.7.1): Only schedule once
if (!profileProvider.isInitialized && !_providerInitScheduled) {
  _providerInitScheduled = true;
```

**Logout callback guard:**
```dart
// Before (v6.7): Fires even after user has re-logged in
WidgetsBinding.instance.addPostFrameCallback((_) {
  if (mounted) _handleLogout();
});

// After (v6.7.1): Won't fire if user already logged back in
WidgetsBinding.instance.addPostFrameCallback((_) {
  if (mounted && _isLoggedOut) _handleLogout();
});
```

### View Logout Handlers (notes_view, profile_view, verify_email_view)

**Standardized pattern across all views:**
```dart
// Before (v6.7): Pushed route on top of AuthGuard
await AuthService.firebase().logOut();
if (!mounted) return;
Navigator.of(context).pushNamedAndRemoveUntil(loginRoute, (_) => false);

// After (v6.7.1): Let AuthGuard StreamBuilder handle navigation
await AuthService.firebase().logOut();
// AuthGuard handles navigation via StreamBuilder
```

**Complete provider resets (profile_view, verify_email_view):**
```dart
// Added missing resets
context.read<NotificationsProvider>().reset();
context.read<ResumeReviewProvider>().reset(); // v6.7
```

## Logout Flow (After Fix)

```
User taps Logout
        ↓
View: Reset all providers (ProfileProvider, PlacementsProvider,
      AIUsageProvider, NotificationsProvider, ResumeReviewProvider)
        ↓
View: await AuthService.firebase().logOut()
        ↓
AuthGuard StreamBuilder fires (user == null)
        ↓
_isLoggedOut = true, _providerInitScheduled = false
        ↓
Schedule _handleLogout() callback (guarded with _isLoggedOut check)
        ↓
Return LoginView
```

## Re-Login Flow (After Fix)

```
User submits credentials → Firebase Auth success
        ↓
AuthGuard StreamBuilder fires (user != null)
        ↓
_isLoggedOut = false, _providerInitScheduled = false
        ↓
Any pending _handleLogout() callback → skipped (isLoggedOut is false)
        ↓
Consumer<ProfileProvider> builder fires
        ↓
_providerInitScheduled = true → schedule initWithUser() ONCE
        ↓
All providers initialized with new userId
        ↓
Return NotesView (with data loaded)
```
