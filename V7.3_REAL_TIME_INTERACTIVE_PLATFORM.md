## Firestore Schema

### New Collections

#### `chats/`
```javascript
{
  participantIds: string[],           // [studentId, alumniId]
  participantNames: {                 // Cached names for display
    studentId: "Student Name",
    alumniId: "Alumni Name"
  },
  relatedMentorshipId?: string,       // Optional link to mentorship request
  lastMessage: string,                // Most recent message text
  lastMessageSenderId: string,        // Who sent the last message
  lastMessageAt: timestamp,           // Last activity timestamp
  createdAt: timestamp,               // Chat creation time
  unreadCount: {                      // Per-user unread counts
    studentId: number,
    alumniId: number
  }
}
```

#### `chats/{chatId}/messages/`
```javascript
{
  chatId: string,                     // Parent chat reference
  senderId: string,                   // Message sender UID
  senderName: string,                 // Sender display name
  text: string,                       // Message content
  sentAt: timestamp,                  // Message timestamp
  isRead: boolean                     // Read status
}
```

### Enhanced Collections

#### `mentorship_requests/` (v7.3 additions)
```javascript
{
  // ... existing v7.2 fields
  chatId?: string,                    // Link to chat conversation
  completedAt?: timestamp,            // Completion timestamp
  rating?: number,                    // 1-5 star rating
  feedback?: string                   // Optional completion feedback
}
```

#### `users/{uid}/notifications/` (v7.3 types)
```javascript
{
  // New notification types:
  type: 'mentorshipRequested'|'mentorshipAccepted'|'mentorshipRejected'|'newMessage'|'newJobPost',
  data: {
    // Type-specific data:
    requestId?: string,               // For mentorship notifications
    chatId?: string,                  // For message notifications
    opportunityId?: string            // For job post notifications
  }
}
```

### Security Rules Enhanced
```javascript
// Chat access - only participants can read/write
match /chats/{chatId} {
  allow read, write: if request.auth.uid in resource.data.participantIds;

  match /messages/{messageId} {
    allow read, write: if request.auth.uid in
      get(/databases/$(database)/documents/chats/$(chatId)).data.participantIds;
  }
}

// Notification creation for new types
match /users/{userId}/notifications/{notificationId} {
  allow read, update: if request.auth.uid == userId;
  allow create: if request.auth != null; // Allow other users to notify
}
```

### 🔧 Recommended Fix: Job Post Notifications

**Current Issue**: Client-side code cannot query all students due to Firestore security rules (intentional protection).

**Recommended Solution**: Create a Cloud Function triggered on new job posts:

```javascript
// functions/index.js
exports.onNewJobPost = functions.firestore
  .document('opportunities/{opportunityId}')
  .onCreate(async (snap, context) => {
    const job = snap.data();
    const studentsSnapshot = await admin.firestore()
      .collection('users')
      .where('role', '==', 'student')
      .get();
    
    const batch = admin.firestore().batch();
    studentsSnapshot.docs.forEach(doc => {
      const notifRef = admin.firestore()
        .collection('users').doc(doc.id)
        .collection('notifications').doc();
      batch.set(notifRef, {
        type: 'newJobPost',
        title: 'New Job Opportunity',
        message: job.title,
        data: { opportunityId: context.params.opportunityId },
        isRead: false,
        createdAt: admin.firestore.FieldValue.serverTimestamp()
      });
    });
    
    await batch.commit();
  });
```

This is the **security-correct approach** - only server-side code (Cloud Functions) should query all users.
